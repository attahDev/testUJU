# Rose Uju storefront

React 19 + Vite storefront for Rose Uju. It talks to the Rose Uju API (FastAPI) for the catalogue, accounts, orders, reviews and admin.

## Run locally

```
cp .env.example .env
npm install
npm run dev
```

`VITE_API_URL` must point at the running API (default `http://localhost:8000`). The API's `FRONTEND_URL` and `CORS_ORIGINS` must include this app's origin (default `http://localhost:5173`).

## Scripts

- `npm run dev` starts the dev server
- `npm run build` creates the production build in `dist`
- `npm run lint` runs Oxlint

## Pages

Home, Shop, Product, Collections, Customise, Cart, Checkout (hands off to Stripe), Order confirmation, Journal, Journal article, About, Account, Reset password and Admin.

## Deploy (Vercel)

Set `VITE_API_URL` to the deployed API URL. `vercel.json` rewrites every path to `index.html` so deep links such as `/order/RU-ABC123` and the Stripe return URL work.

## Admin

Sign in with an admin account at `/account`, then open Admin. Manage products, journal articles, orders (status and refunds), comments and reviews.

## Search and link sharing

- **Page titles, descriptions and canonical links** are set per page by `src/hooks/usePageMeta.js`. Private pages (bag, checkout, account, orders, admin, wishlist, 404) are marked `noindex`. Product pages also carry schema.org product data (price, currency, stock) for Google.
- **Link previews** (WhatsApp, Facebook, Slack, Telegram, ...) do not run JavaScript, so `vercel.json` sends only those bots to `api/og.js`, which returns a small page with the right title, description and photo for the product, Journal article or homepage. People and search engines get the normal site. The homepage card uses the hero photo from Admin > Site images once you upload one.
- **`/sitemap.xml` and `/robots.txt`** are generated by `api/sitemap.js` and `api/robots.js` from the live catalogue.
- The default share card is `public/og-default.jpg` (1200x630). Replace it with your own image of the same size whenever you like.

### Settings (Vercel environment variables)

| Variable | Purpose |
|---|---|
| `VITE_API_URL` | Your backend address (already required). The preview functions use it too. |
| `VITE_SITE_URL` | Your live site address, e.g. `https://www.roseuju.com`. Stamped into the share tags at build time. If unset on Vercel it falls back to the project's `.vercel.app` address, so set it once your domain is connected, then redeploy. |

### Checks

`npm run test:seo` tests the functions and the bot matching in `vercel.json` against a fake backend. After deploying, confirm a real preview: run `curl -A "WhatsApp/2.23" https://YOUR-SITE/product/1` and look for `og:title` and `og:image`, then paste a product link into WhatsApp or the Facebook Sharing Debugger. Previews are cached by those apps, so use the debugger's re-scrape button after changing a photo.

## Sharing

`src/components/ShareButton.jsx` is used on products, looks and Journal articles. Phones open the system share sheet (WhatsApp, Instagram, Messages, ...); computers get a menu with WhatsApp, Facebook, X, email and copy-link. Each look has its own page at `/looks/<name>` so it can be shared, and link-preview bots get a proper card for it from `api/og.js`.
